## What it is

`flawless-react` is a multi-task quality kit for React components. Point it at a `.tsx` file
(or a glob such as `src/**/*.tsx`), pick which of the seven tasks to run, and it reads each
component's type signature, walks its JSX to discover locally-imported children, and produces
a runnable Playwright + Vitest suite, an accessibility scan, and a Biome-driven correctness
report — with file:line findings for every issue. Run it with no arguments for an interactive
checkbox menu. The generated suite is a standalone project that knows nothing about the tool
once written. A re-run regenerates derived files so they track your source, while the files
meant to hold your work — budgets, host wrapper, provider fixtures, MSW handlers, colocated
specs — are write-once or kept: tighten budgets, add scenarios and swap in real fixtures
like any other test code.

<InstallBlock />

That is the standalone binary — no Bun needed on the target machine. The source package
(`bun add -g flawless-react --registry https://npm.in.drlario.org`) needs Bun >= 1.1 but
carries `@biomejs/biome` as a real dependency, so every task works with no further setup.
The difference matters for two of the seven tasks; see [Install](/docs/install/).

## At a glance

The seven task ids, and what each one leaves behind:

| Task id | What it produces |
| --- | --- |
| `perf-harness` | A Playwright suite driven by React's built-in `<Profiler>` and `react-scan` — a bundled host page, one spec per analysed component, per-component `budgets.json`, and `.heapsnapshot` files under `heaps/`. |
| `unit-browser` | Vitest + `@testing-library/react` unit tests plus Playwright functional browser specs for every component in the tree. |
| `perf-static` | `reports/<Component>.perf-static.json` — rerender and memoisation risks (children rendered with no `useMemo`/`useCallback`/`memo`/`useRef`) and props the analyser could not synthesise a default for. |
| `a11y` | `reports/<Component>.a11y.json` — Biome's accessibility rules over the targeted tree, as file:line findings. |
| `react-rules` | `reports/<Component>.react-rules.json` — a curated set of bug-catching React and hooks rules via Biome (`useExhaustiveDependencies`, `useHookAtTopLevel`, `useJsxKeyInIterable`, and friends), bypassing any local `biome.json`. |
| `e2e` | `e2e/<route>.spec.ts` — one Playwright spec per app-router page: the route loads with no console or page errors, plus interactions harvested from its component tree. Next.js mode only. |
| `load` | `load/routes.pipes` — crust load pipes per route and per API operation. Each run writes `load/last-<name>.json`; you promote one to `load/baseline-<name>.json` by hand, and later runs then fail when p95 exceeds 2x it. |

Findings also surface where the code lives: a small `<Component>.flawless.json` is dropped next
to each source file unless you pass `--no-inline-summary`.

`perf-harness`, `unit-browser`, `perf-static`, `e2e` and `load` run anywhere. `a11y` and `react-rules` shell
out to biome, which the binary cannot carry inside itself — it looks for biome in the project
being scanned (`node_modules/.bin/biome`) and then on `PATH`.
